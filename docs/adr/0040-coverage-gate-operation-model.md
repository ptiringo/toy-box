# 0040. カバレッジゲートの運用モデルを excludes 反転 + LINE/BRANCH 2 ボーンド + 手動ラチェットで構成する

- Status: Accepted
- Date: 2026-06-30
- Deciders: Matsui

## Context（背景・課題）

[ADR-0006](0006-kover-over-jacoco.md) で Kover を採用し、「成熟パッケージのみ `includes` フィルタで絞ったゲート（`variant("mature")`）」を設けた。
しかし導入後、以下の問題が顕在化した。

### includes 固定列挙の維持コスト

`mature` variant の `includes` に列挙されたパッケージだけがゲート対象になる設計では、
コンテキスト分割（#354: `horseracing` → `studbook` / `racing`）のたびにパッケージ名の変更を
`includes` 一覧に手反映する必要があった。
また #312 inspection サブドメインのように、実装・テストが完成して「成熟」しているにもかかわらず
`includes` に追記を忘れた結果、ゲート対象外のまま取り残されるケースが実際に発生した。

### LINE のみのゲートが条件分岐の穴を見逃す

ADR-0006 時点のゲートは**行カバレッジ（LINE）のみ**であり、条件分岐の片側が未テストのまま
通過できるケースがあった。

### 問題の構造

これら 2 点は「**追加を忘れると安全側ではなく危険側に倒れる**」設計に由来する。
新しい成熟コードが既定でゲートに含まれるよう、包含の向きを反転させる必要があった。

## Decision（決定）

### 1. ゲート対象を excludes 反転で決める

`variant("mature")` の `includes` 固定列挙を廃止し、**全体をゲート対象としたうえで
探索段階のパッケージだけ `excludes` に列挙する**方式に切り替える。

現状の `excludes`（探索除外）:

- `com.example.api.domain.racing.model.race`（Race 集約）
- `com.example.api.domain.racing.service`（レースドメインサービス）
- `com.example.api.domain.sakamichi`（エンターテイメントコンテキスト）
- `com.example.api.domain.tennis`（スポーツコンテキスト）
- `com.example.api.e2e`（E2E テスト基盤クラス）

この方式では、**新しい成熟コードは明示的な `excludes` 追加なしにゲート対象へ自動で取り込まれる**。
追加を忘れた場合は「より厳しくなる（ゲートが赤くなる可能性がある）」安全側に倒れる。

### 2. カバレッジ単位を LINE + BRANCH の 2 ボーンドにする

- **LINE**: 行の到達性を計測。母集団変更後の実測 94.57% の直下のキリ番として **90%** を下限とする。
- **BRANCH**: 条件分岐の網羅を計測。実測 84.91% の直下のキリ番として **80%** を下限とする。

これにより、行が到達していても条件分岐の片側が未テストのまま通過するケースを検出できる。

### 3. 閾値は手動ラチェットで維持する

自動ラチェット機構（CI が閾値を書き換える等）は作らない（YAGNI）。
上がったタイミングで人間が `build.gradle.kts` を手動更新し、下限を引き上げる運用とする。
下げるときは設計上の判断が要るため、手動であることが望ましい。

### 4. 差分カバレッジ（patch coverage）は #437 に委譲する

本 ADR が扱うゲートは**成熟領域全体の絶対水準**を守る集約ゲートである。
新規変更コードの行カバレッジ（patch coverage）は補完的な別概念であり、#437 で別途検討する。

## Consequences（結果・影響）

- **安全側の失敗**: 新しい成熟コードはデフォルトでゲートに含まれ、追加忘れが「通過できなくなる」側に倒れる。
- **探索コードは excludes 維持が必要**: 探索段階の領域を増やすときは `excludes` への追加が必要。ただし追加を忘れても「通過できなくなる」だけで、誤緩和は起きない。
- **BRANCH ゲートで条件分岐の穴を検出**: LINE 単独より実効的なカバレッジ保証になる。
- **旧 85% 基準の廃止**: 母集団が変わったため、ADR-0006 で定めた「LINE 85%」は本 ADR の「LINE 90% / BRANCH 80%」に置き換わる。
- **ADR-0006 は不変**: ツール選定（Kover over JaCoCo）と「成熟領域のみゲートする」方針は変わらない。本 ADR は運用モデルの詳細のみを扱う。
