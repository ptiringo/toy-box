# 0087. 持込馬を sealed な種付と出自のバリアントで表し、外国種牡馬は値として埋め込む

- Status: Accepted
- Date: 2026-10-23
- Deciders: ptiringo / Claude Code

## Context（背景・課題）

繁殖 replay ハーネスに実在の持込馬（ウインドインハーヘアが 1999 年にアイルランドでデインヒルと種付し、2000 年に日本で
ライクザウインドを産んだ例）を流したところ、モデルにはこの経路を表す手段が無かった（#624）。種付（`Covering`）は
日本の繁殖登録を持つ種牡馬の ID と日本の種畜証明書を前提にしており、フィクスチャは架空の輸入年月日と繁殖登録番号を
与えて事実を歪めることでしか一周させられなかった。

JAIRS 登録規程（`https://www.jairs.jp/contents/pdf/tourokukitei.pdf`、決定時点の最終改正は令和元年12月27日）を原文で確認した事実:

- 持込馬は「その馬の生産に係る種付けが外国で行われた馬であって、輸出国出国以降に生まれたもの」で、内国産馬の一部として
  定義される（「内国産馬（持込馬を除く。）」という書き方。第6条第1号）。
- 持込馬の申込資格は「その母馬が繁殖登録を受けたもの」だけで、父の JAIRS 繁殖登録は求めない（第6条第3号）。
- 添付書類は母馬の繁殖登録証明書と、母馬が種付けを受けた国の血統登録機関が発行した種付けの事実を証明する書類（第8条第1項第4号）。
- 登録要件のうち「種畜証明書を有する種雄馬の種付けによる産駒」は持込馬に適用しない（第15条柱書）。DNA 親子判定・毛色の
  親子整合などその他の要件は適用される。

検討した案:

- **持込馬専用の登録経路を別に作る**（繁殖成績を経由せず、海外の種付証明を直接入力にして産駒を登録する）。既存の
  チェーンに手を入れずに済むが、母の繁殖成績（様式第14号）にその年の分娩が載らず、年次成績が 2 系統に割れる。採らない。
- **外国種牡馬を `BloodHorse` として登録して参照する**。今のフィクスチャの回避策を正規化することになり、JAIRS に
  登録されていない馬を登録済みとして扱う＝事実の捏造をモデルに組み込む。採らない。
- **`Origin.Domestic` の父を sealed にして外国種牡馬も持てるようにする**。規程の「内国産馬の一部」という構造には
  素直だが、`Domestic.sireId` を読む箇所と `blood_horse.sire_id` の FK・CHECK をすべて分岐させることになる。採らない。

## Decision（決定）

1. **種付 `Covering` を sealed にし、`Domestic`（国内種付）と `Overseas`（海外種付）に分ける。** `Overseas` は外国種牡馬・
   種付日・種付国・種付国の機関が発行した種付事実の証明の番号を持ち、種畜証明書による検証を掛けない。繁殖成績 →
   分娩報告 → 産駒登録のチェーンは 1 本のまま、どちらの種付でも同じ繁殖成績に載せる。
2. **産駒の出自に `Origin.BroughtIn(sire: ForeignSire, damId)` を足す。** `Domestic` は拡張しない。規程上は内国産馬の
   一部であることは KDoc に明記する。持込馬の血統登録は `BloodHorse.createBroughtIn` が、母が雌・DNA 親子判定・品種整合・
   毛色整合を `create` と同じ検証で外国種牡馬の属性に対して行う。国内の経路（`registerFoal`）は海外種付の成績を
   `NotDomesticCovering` で拒否し、持込馬は `registerBroughtInFoal` で登録する。
3. **外国種牡馬は集約にせず、値オブジェクト `ForeignSire`（馬名・登録機関の国・品種・毛色）として種付と出自に埋め込む。**
   同じ外国種牡馬を複数の種付で名寄せする同一性は扱わない。
4. 永続化は ADR-0043 に従い、判別子列（`breeding_result.covering_type`、`blood_horse.origin_type = BROUGHT_IN`）と
   バリアント固有列でフラット化し、判別子ごとの「全 NULL／全 NOT NULL」を CHECK 制約で強制する（V24 / V25）。

原典で確認できなかった不変条件はモデルに入れない。具体的には「輸出国出国以降に生まれた」（母の出国日をモデルが持たない）、
受胎中の輸入や揚陸日と出生日の関係、在胎期間の妥当性（第15条第2項。持込馬に限らない論点）。

## Consequences（結果・影響）

- 繁殖成績は国内種付・海外種付・種付せずのいずれでも「繁殖牝馬 × 繁殖年」に 1 つで、一意性の検証も共通化された。
  種牡馬の年次集計（様式第2号）は `covering_stallion_id` で絞るため、海外種付は自然に対象外になる。
- 判別子 `covering_type` は種付せずの年に NULL を取る nullable 列なので、CHECK 制約の比較の前に `IS NOT NULL` を置いている。
  `covering_type = 'DOMESTIC'` は NULL のとき NULL を返し、CHECK は NULL を違反とみなさないため、埋め戻し漏れの行が素通りする
  （V24 の作業中に契約テストで実測）。nullable な判別子に CHECK を張るときは同じ形にすること。
- 外国種牡馬の同一性を持たないので、「デインヒルの産駒一覧」のような外国種牡馬起点の照会はできない。必要になったら
  別の決定で外国種牡馬を集約にする。
- 輸入牝馬が JAIRS の血統登録を経ずに直接繁殖登録を受ける経路（第7条第2号、揚陸日から 90 日の期限）は今のモデルに無く、
  replay では輸入馬の血統登録で代用している。別の Issue で扱う。
- 応答では `BreedingResultResponse` に `covering_type` / `foreign_sire` / `covering_country` / `proof_number` を、`OriginDto` に
  `BROUGHT_IN` を追加した（既存項目は不変）。入力側（海外種付の記録と持込馬の登録の API）は後続の PR で足す。
- 繁殖成績の応答の種付は、`origin` のような判別子つきの入れ子（oneOf、api-design.md / ADR-0020）にせず、**平置きのまま
  項目を足す**。既存の国内種付の項目（`stallion_id` / `covering_place` / `certificate_number`）が既に平置きで公開されており、
  入れ子を足すと同じ事実を二重に表すことになるため。入力（`covering {…}` の入れ子）と出力（平置き）の非対称は国内種付の時点から
  あり、海外種付で新たに生じたものではない。入れ子へ寄せるなら、既存項目の廃止を伴う別の決定として扱う。
