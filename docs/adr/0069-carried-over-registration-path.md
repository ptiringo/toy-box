# 0069. 内国産既存馬はシステム境界の移行取り込み経路で血統登録する

- Status: Accepted
- Date: 2026-07-22
- Deciders: ptiringo

## Context（背景・課題）

血統登録の入口は `RegisterInStudBookUseCase`（内国産馬・父母あり）と `RegisterImportedHorseUseCase`（輸入馬・父母不明で原産国・揚陸日を持つ、[ADR-0020](0020-sealed-origin-and-discriminated-origin-subobject.md)）の 2 つしかなく、**すでに日本で生まれ繁殖に上がっている内国産馬を、事実どおりの経路で系に入れる手段が無い**。

この歪みは replay（フィクスチャによる既存データ再現）で表面化した。シーザリオ・テスコパール・ドゥラメンテはいずれも内国産の基礎馬だが、登録できる経路が輸入馬しか無いため、架空の揚陸日を与えて輸入馬として登録していた（[#619](https://github.com/ptiringo/toy-box/issues/619) で発覚、[#633](https://github.com/ptiringo/toy-box/issues/633)）。この歪みは「登録できず停止する」ではなく「フィクスチャ側が事実を捏造して吸収する」形で隠れており、ドメインモデルの表現力不足が replay の正確性を侵していた。

### 原典裏取り（2026-07-22 実施）

JAIRS「登録規程実施基準」（全 49p、最終改正 令和5年11月30日）と「登録料及び手数料の料金表」を精読した（p.1〜16 は全ページ画像化して精読、p.17〜49 は様式・付録のみと確認）。射程は**この 2 文書の範囲**であり、上位の「登録規程」本体は未読のため、以下の断定はいずれも「実施基準と料金表の範囲では」に限定される。

1. **期限超過馬の遡及登録・超過登録の規定**: 該当規定なし（条文 p.1〜6・附則 p.6〜9 の全条文を確認）。時期に関する唯一の規定は第 6 条第 2 項（p.2）「血統登録の審査は、原則として離乳前に行う。ただし、やむを得ない場合は、申込み後すみやかに審査を行う」であり、これは審査時期の弾力化であって申込期限超過の救済ではない。料金表（全 1 ページ）の血統登録料（サラブレッド・サラ系種）は「当歳の 11 月 30 日まで 16,000 円／1 歳の 12 月 31 日まで 32,000 円」の 2 区分のみで、「2 歳以上」「期限後」の区分が存在しない。母馬（繁殖登録雌）側には遅延受付の割増区分があるが、終点が「産駒の血統登録申込の日」であり産駒の期限超過を救済するものではない。
2. **登録原簿への移行・引継ぎ（旧血統書からの取り込み）の規定**: 経路規定なし。附則（p.6〜9）の経過措置はすべて施行日・旧様式の読み替えの類で、旧登録簿からの馬の移行・遡及登録に関するものは無い。ただし繁殖登録原簿様式第 2 号（p.16）には「Stud Book 記録（第 巻 頁）」「血統書記録（第 巻 頁）」の相互参照欄が実在し、「先行する原簿に記録済みの血統を参照で指す」という**概念自体は制度に存在する**（登録経路としてではなく記載項目として）。
3. **血統登録要件（母の繁殖登録証明書・種付証明書。[#267](https://github.com/ptiringo/toy-box/issues/267) で確定）の例外・免除規定（輸入馬以外）**: なし。第 9 条（p.3）は要件を厳密化する方向の解釈規定であり、第 3 条・第 4 条第 3 項の救済・代替規定はいずれも別の場面（繁殖登録前死亡馬の救済、輸入馬の電送書類代替）を対象とする。

結論: 通常の血統登録時期を過ぎた内国産馬を、母の繁殖登録証明書・種付証明書なしで血統登録／登録原簿に載せる経路は、実施基準・料金表の範囲では制度上存在しない。

### 検討した代替案

- **案 A: `Origin.Imported` の一般化**。輸入馬と同じバリアントで表現する案だが、輸入馬は「原産国の揚陸日起算」という実手続を型で表しており（ADR-0020）、そこに移行取り込み（揚陸日を持たない）を混ぜると型強制が弱まる。
- **案 B: replay 専用の seed 分岐（モデル変更なし）**。フィクスチャ側だけで吸収する現状の延長であり、ドメインモデルの歪み（内国産馬を輸入馬として表現する無効状態）が残る。
- **案 C: 輸入馬経路で原産国「日本」を許容する**。輸入馬の原産国を「日本」とすれば型変更なしで登録できるが、外国から輸入した事実を持つ輸入馬の意味と衝突し、これを禁じる制度上の典拠も存在しない一方、実務上は明らかに不自然。
- **案 D: 父名・母名・旧原簿の巻・頁参照を属性として保持する**。様式第 2 号（p.16）の相互参照欄に倣う案だが、現時点でこれらを使う機能要求が無く YAGNI であり、replay 実装では全件が合成値になってしまう。

## Decision（決定）

`Origin` に第 3 バリアント `CarriedOver`（`@ValueObject data object`、属性なし）を追加し、「JAIRS の業務手続ではなく、システム境界での移行取り込み」として明示的にモデル化する。`Domestic` / `Imported` / `CarriedOver` は sealed により引き続きコンパイル時に相互排他が強制される（ADR-0020 の延長）。

- **ドメイン**: `domain/studbook/model/horse/bloodhorse/Origin.kt` に `CarriedOver` を追加。`BloodHorse.createCarriedOver(entry, inspection, registrationNumber)` を新設し、父母の検証対象が系内に存在しないため `createImported` と同じく前提条件検証なしで直接 `BloodHorse` を返す。入力束 `CarriedOverHorseEntry` は `StudBookEntry` / `ImportedHorseEntry` と同じ慣習で経路ごとに型を分ける。審査は `ParentageDetermination.NotApplicable` を輸入馬・移行取り込み共通の意味へ一般化して再利用する。
- **application 層**: `RegisterCarriedOverHorseUseCase` + `RegisterCarriedOverHorseCommand` を輸入馬ユースケースと対称の構造で追加する。
- **REST**: `POST /api/bloodHorses:registerCarriedOver`（既存 `:registerImported` と同じカスタムメソッド形式）。レスポンスは既存の統一リソース表現 `BloodHorseResponse` を維持し、出自の discriminated 部分オブジェクトに `CARRIED_OVER` を追加する（ADR-0020 の枠組みをそのまま適用）。
- **永続化**: `origin_type` の許容値に `CARRIED_OVER` を追加し、バリアント固有列を持たないため `CARRIED_OVER` のとき `sire_id` / `dam_id` / `origin_country` / `landing_date` がすべて NULL であることを CHECK 制約（`chk_blood_horse_origin`）で強制する（`V15__update_blood_horse_origin_check.sql` で `NOT VALID` 追加、`V16__validate_blood_horse_origin_check.sql` で `VALIDATE CONSTRAINT`。[ADR-0052](0052-validate-constraint-in-separate-migration.md) の 2 ファイル分離規約に従う）。
- **replay**: seed の経路選択を `facts.originCountry == "日本"` かどうかから事実ベースで導出する。内国産の基礎馬（シーザリオ・テスコパール・ドゥラメンテ）は移行取り込み経路、外国産の基礎馬（ウォーエンブレム等）は従来どおり輸入経路とし、架空の揚陸日と `#633` 断り書きをフィクスチャから削除する。

## Consequences（結果・影響）

- replay の合成データから架空の揚陸日（内国産馬に対する輸入馬なりすまし）が消え、フィクスチャが「事実どおり」に戻る。`origin_type` は `DOMESTIC` / `IMPORTED` / `CARRIED_OVER` の 3 値になる。
- 輸入馬経路の replay カバレッジは外国産の基礎馬で引き続き維持される。
- 本 ADR の「制度上存在しない」という断定は、原典裏取りの射程（登録規程実施基準・料金表）の範囲に限定される。上位の「登録規程」本体は未読であり、それが遡及登録・移行手続を別途定めている可能性は排除できない（原典裏取りの詳細は [#633](https://github.com/ptiringo/toy-box/issues/633) のコメントに記録）。
- 却下した 4 案（`Imported` の一般化・replay 専用 seed・輸入馬での原産国「日本」許容・父名母名や旧原簿参照の保持）はいずれも採らない。父母不在時の 422 判断（[ADR-0021](0021-parent-not-found-unprocessable-entity.md)）は移行取り込み経路には適用されない（父母 ID を持たないため参照検証自体が発生しない）。
- 用語集（`docs/ubiquitous-language.md`）に「移行取り込み」の語彙を追加した。今後、既存原簿からの取り込みを模した経路を追加する際は、本 ADR の「システム境界の移行経路であり JAIRS 手続ではない」という位置づけの区別を踏襲する。
